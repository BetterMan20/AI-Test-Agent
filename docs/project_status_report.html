AI-Test-Agent 项目状态报告

一条「认识 → 建模 → 找风险 → 攻击 → 验证 → 回归 → 学习」的 AI QA 基础设施，定位是让测试 Agent 从"会生成测试用例的 AI"迈向"会探索 App 并长期积累质量的 AI 测试 Agent"。

核心结论：在既有 S1–S6 执行引擎（v0.8，发红包/送礼/进房三能力抓包回放跑通、三层解耦）之上，本轮完成了三件里程碑—— ① S0 长期 App Knowledge Base + App Explorer：Agent 自主下钻并落盘 页面/控件/状态/跳转/截图/XML，反幻觉约束（只记真机实测，不伪造节点）已生效； ② 一致性攻击引擎 + 历史 Bug 反推：在 Room 14775 真机复现"OPEN + 未开始领取"状态冲突并留档证据（reproduce_report.json/ui/png）； ③ 全景 QA 循环 + LLM 三环：认识→学习 七阶段跑通，且按你定的方向（让 LLM 拿到越来越完整的系统事实 + 越来越强的执行能力 + 越来越多的历史质量知识）接好三环——A=KB→LLM 系统事实注入、B=LLM 在可达原语上编排攻击、C=历史记忆进找风险，三环全部"真实消费"。历史质量库已做根因级去重（4→2 条、幂等、可增量不膨胀）。整体定位从"生成用例/跑回归"升级为持续让 LLM 拥有更足输入、让 KB 与历史长期自积累的 Agent。

关键点（回应"不是让 LLM 变得更聪明"）：模型权重从未改动。所有的"变强"都发生在输入端——更全的系统事实（A）、更多可执行原语与执行闭环（B）、更厚的历史质量知识（C）。真正的执行能力天花板在可达原语仓库：原语少，LLM 能选的路径就少；原语多，它的选择空间才大。

4. 全景 QA 循环（认识 → 攻击 → 学习）

core/qa/cycle.py 提供业务不可知的通用编排器，七阶段逐阶段标记 wired/via/pending；业务差异全部走 QADriver 接口注入（符合"Core 不含业务"分层约束）。

[认识]   S0/KB → system_facts          → wired（探索+capability）
[建模]   red_packet_claim.json(4状态) → wired
[找风险] 9 risks(5攻击向量+4历史)     → wired（+C 历史反推）
[攻击]   4 定向测试点(RP-001~004)      → wired（+B LLM 决策/原语编排）
[验证]   判真实违例 WAITING/OPEN        → wired（确定性 check_consistency）
[回归]   一致性回归 relive=2 breaks=2  → wired
[学习]   观测回填 KB + 历史追加(去重)   → wired

开关全部默认关闭（use_llm_attack / use_llm_risk / real_fact_extraction），不引入默认成本/抖动；逐个开启即从确定性退化为 LLM 增强，且 LLM 失败自动回退，循环不中断。

A. 系统事实注入（core/qa/kb_facts.py + 抽取/设计接参）

  • KB 渲染为 LLM 可消费的 system_facts，每状态带反幻觉标记 (实测)/(声明)，如 可领取: UI=OPEN (实测)。
  • SkillEngine.run 增 extra_context 独立分块追加到 system_prompt；fact_extraction/test_design 均接收 kb_facts。
  • 真实消费验证：real_fact_extraction=True 下真调抽取模型，从 KB 简报抽出 17 条结构化事实（OBJECT/STATE/RELATION/CONDITION），"实测/声明"区分随入——System Prompt 长度 7324，含"额外系统上下文"权威事实块。

B. 可达原语编排执行（core/attack/llm_advisor.py + QADriver.reachable_primitives/execute）

  • 决策输入含真实可执行原语清单（Higo 4 条：open/dump/close/refresh red_packet），约束"只能从清单里编原语、不发明路径"。
  • 决策输出 selected_paths + per_path.primitives；cycle 把原语序列交给 driver.execute 真执行、回读观测并入验证；设备/原语不可达时诚实返回 executed=False，绝不假点击。
  • 真 LLM 实测（42s）：模型发现路径动作 refresh_state/close_popup 不在清单后自纠错，改写映射到真实存在的 refresh_red_packet_state/close_red_packet 重新纳入 RP-003/004，并保住 RP-005（原语缺失→不选）。最终 4 条路径原语全部 ⊆ 可达清单（越界 0）。

C. 历史记忆进找风险（core/qa/historical_memory.py）

  • render_historical_memory 把 historical.yaml 渲成"已发生过的 bug"记忆块；llm_augment_risks 让 LLM 从历史规律泛化新风险。
  • LLM 实测（27s / 3469 tok）：从历史违例反推出 5 个新风险（R-H-01 状态值异常 / R-H-02 状态转换边界 / R-H-03 状态同步 / R-H-04 状态覆盖 / R-H-05 状态持久化），真实引用历史 id，非模板套话。

7. 结论与建议下一步

已确立的价值

  • 探索力：Agent 能自主下钻、落库、记忆 App 结构；反幻觉约束保证"只记真的、不伪造节点"。
  • 发现力：一致性攻击引擎 + 历史 Bug 反推，真机复现"OPEN + 未开始领取"状态冲突并存档。
  • 自积累：LLM 三环让"系统事实 + 执行能力 + 历史质量"三个输入随运行越来越足，且执行→学习→回填 KB/历史形成持续闭环。
  • 可控成本：三个 LLM 开关默认关，退回确定性；LLM 失败自动兜底，不影响回归。

已知局限

  • S0 的完整现场下钻依赖设备处于"直播间 + 屏幕有未开花红包入口"状态；当前多次只探到"Room + 未发现入口"便诚实停住，未伪造（反幻觉正确但覆盖受限）。
  • B 的 execute() 前置校验与不可达返回已就绪并通过离线验证，但现场真执行需设备就绪后才跑；待开奖→倒计时(COUNTDOWN)分支需"未来 open_at"红包场景。
  • A 抽取结果未给 fact 附加 provenance(声明/实测) 字段，声明节点与实测节点在抽取产物里暂区分粒度不足。

建议下一步

  1. S0 定时探索：把 run_qa_cycle 挂成每日定时任务，让 KB + 历史 + 可达原语长期自动积累（回应"不是一次性跑完"）。
  2. 补全现场分支：在"未来 open_at 红包"环境下补记 待开奖→COUNTDOWN 分支；B 真机执行闭环现场跑通。
  3. 抽取溯源增强：给抽取到的 fact 补 provenance(声明/实测)，强化"显式事实 vs 推断事实"区分。
  4. 可达原语扩充：把执行能力做成显式清单（capabilities.yaml：原语+前置条件+证据格式），让 LLM 探索/决策只从"真能执行"里挑——这才是"更强执行能力"的落点。
